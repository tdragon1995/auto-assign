# Activity-log line templates

Every line stored in the live log (Redis `assign:run_log`) and shown in the
dashboard. **Uniform convention:** each line carries a single ` | ` and ends with
`<pickup> → <dropoff>`, so the customer/route is always the one trailing field.
All other detail (driver, shift, reason, …) goes before that ` | `, separated by
commas/colons. This makes the Quản trị job search parse trivially:
`customer = msg.split(" | ").pop()`.

Generated by `log(...)` in `assign.ts` (+ `return-trips.ts`, `via-legs.ts`) and
`pushRunLog(...)` in the API routes.

**Stored?** = whether `shouldStore` (smart-log-kv.ts) keeps it in the live log.
Recurring per-job failures are dropped (they show in the Cần xử lý panel instead);
most INFO is dropped unless it matches `INFO_KEEP_PATTERNS`. Dropped lines never
reach the search.

## Other route loggers (pushRunLog)

| Template | Source | Notes |
|---|---|---|
| `[Sales] Huỷ job: Job <id>, Ref: <ref>, Lý do: <r> \| <pickup> → <dropoff>` | api/sales/reject-job | real CT names (reject flow already fetched the job) |
| `Job <id> - Đã lên lịch / Đã duyệt / THẤT BẠI … \| <pickup> → <dropoff>` | api/assign/held | real CT names (held flow fetches the job) |
| `[Sales] Tạo chuyến B2B: Job <id>, Ref: <ref> \| <dropoff PSC>` | api/sales/create-trip | **no route** — see below |
| `[AO] Tạo job lấy kết quả: Job <id> \| <vendor>` | api/ao | **no route** — see below |
| `[PSC-tỉnh] Tạo chuyến: Job <id>, ETA <e>, Ref: <ref> \| <psc>` | api/psc-tinh | **no route** — see below |

**Why the 3 creation routes don't carry `<pickup> → <dropoff>`:** at creation time
the request only holds `customer_id` (the repo rule is *never* send `customer_name`
— Cartrack resolves it from the id). Resolving the real CT name there would need an
extra `getCustomerById` call, so these keep the one real identifier already in scope
(the PSC name, vendor name, or PSC code) instead of a fabricated route.

## System lines (no Job ID, no customer)

`🟢 ENGINE ARMED by <who> (<env>)` · `🔴 ENGINE DISARMED by <who> — <reason>` ·
`🟢 ENGINE AUTO-ARMED (05:30–22:00 window)` · `Found N unassigned job(s)` ·
`Smart-assign ready: N candidate driver(s) …`

## Parser

`extractCustomer` (api/admin/search-jobs) = `msg.split(" | ").pop()` — the route is
always the trailing field, so no field-position guessing. Keep this invariant when
adding new templates: **exactly one ` | `, route last.**
